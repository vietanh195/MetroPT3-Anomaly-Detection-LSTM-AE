# Design System Specification: Technical Precision & Tonal Depth

## 1. Overview & Creative North Star: "The Synthetic Sentinel"

This design system is engineered for high-stakes industrial environments where clarity is a prerequisite and reliability is a mandate. We move beyond the "flat dashboard" trope to embrace **The Synthetic Sentinel**—a creative North Star that treats the interface as a high-performance machine. 

Instead of a generic grid of boxes, this system utilizes **Tonal Layering** and **Asymmetric Information Density**. We favor intentional negative space to reduce cognitive load during critical events, using high-contrast accents only when the data demands action. The aesthetic is "Technical Brutalism" meets "Modern Aerospace": it is rigid in its logic but fluid and sophisticated in its execution.

---

## 2. Colors & Surface Logic

The palette is rooted in a deep, nocturnal base (`#131313`) to eliminate glare in control rooms. We use a "Signal-to-Noise" color strategy: the interface remains monochromatic and muted until a status change triggers the high-chroma accent tokens.

### The Surface Hierarchy (The Layering Principle)
Depth is created through "Nesting," not borders. 
*   **Base Level:** `surface` (#131313) — The foundation of the application.
*   **Secondary Zones:** `surface_container_low` (#1c1b1b) — Large content areas or sidebar backgrounds.
*   **Actionable Cards:** `surface_container` (#201f1f) — Primary interactive containers.
*   **Highlighted Nodes:** `surface_container_high` (#2a2a2a) — Elements that need to stand out from the grid.

### Key Rules
*   **The "No-Line" Rule:** 1px solid borders are strictly prohibited for sectioning. Boundaries must be defined solely through background shifts between `surface` tiers. 
*   **The "Glass & Gradient" Rule:** Use `surface_bright` with a 40% opacity and 20px backdrop-blur for floating overlays (modals/tooltips). For primary actions, use a subtle linear gradient from `primary` (#4be277) to `primary_container` (#22c55e) at a 135-degree angle to provide a "machined" metallic sheen.
*   **Signal Colors:**
    *   **Success/Normal:** `primary` (#4be277)
    *   **Warning/Caution:** `secondary` (#ffca45)
    *   **Alarm/Critical:** `error` (#ffb4ab) or `tertiary_container` (#860011)

---

## 3. Typography: The Information Hierarchy

We utilize **Inter** for its neutral, neo-grotesque clarity. It provides the "Technical" feel required for SCADA without the dated look of monospace.

*   **Display (lg/md/sm):** Used for massive, "at-a-glance" metrics (e.g., total power output). These should be tracked-in slightly (-2%) for a tighter, more urgent feel.
*   **Headline & Title:** Used for system sectors and machine IDs. These are the anchors of the layout.
*   **Body (lg/md/sm):** Default for data tables and logs.
*   **Label (md/sm):** Specifically for technical metadata, timestamps, and unit measurements (e.g., "kW/h"). These should be set in `on_surface_variant` (#bccbb9) to recede visually.

**Identity Note:** Combine `headline-sm` for machine names with a `label-sm` unit measurement immediately following it. This "Big Value, Small Unit" pairing creates a professional, instrumentation-grade aesthetic.

---

## 4. Elevation & Depth

We eschew "material" shadows for **Atmospheric Depth**.

*   **Ambient Shadows:** For floating elements, use an extra-diffused shadow: `offset: 0, 24px; blur: 48px; color: rgba(0, 0, 0, 0.5)`. 
*   **The "Ghost Border" Fallback:** If a container sits on a surface of the same color, use a 1px border of `outline_variant` (#3d4a3d) at 20% opacity. It should feel like a faint reflection on glass, not a stroke.
*   **Tonal Stacking:** An "Alarm Card" should not just have a red border; it should transition to `surface_container_highest` with a faint `error` tinted glow at the bottom edge to simulate a physical warning light.

---

## 5. Components & Data Visualization

### Data Visualization (The Core)
*   **Line Charts:** Use a stroke width of 2px. No area fills under the line unless it represents a cumulative volume. Use `primary` for the line and `outline_variant` (10% opacity) for the grid.
*   **Radial Gauges:** Use a thick `primary` track and a `surface_container_highest` background track. Avoid skeuomorphism; keep it flat and mathematical.
*   **Status Indicators:** Small 8px circles. Use "Pulse" animations (opacity 1.0 to 0.4) for `error` states to draw the eye without using intrusive popups.

### UI Primitive Elements
*   **Buttons:**
    *   **Primary:** `primary_container` background with `on_primary_container` text. Roundedness: `sm` (0.125rem) for a sharper, industrial look.
    *   **Tertiary:** Ghost style. No background, only text.
*   **Input Fields:** Use `surface_container_lowest` for the field background. Labels must be `label-md` and always visible (no floating labels that disappear).
*   **Cards & Lists:** **No Dividers.** Use `8px` of vertical whitespace (Spacing Scale) to separate list items. If separation is needed, use a subtle background toggle between `surface_container` and `surface_container_high`.
*   **Chips:** Use for "Mode Selection" (e.g., Manual vs. Auto). High-contrast `secondary` (#ffca45) for the active state to ensure it is never missed.

---

## 6. Do’s and Don’ts

### Do
*   **Do** embrace asymmetry. If a machine's data is more critical, give its container 60% of the grid width, leaving the others at 40%.
*   **Do** use "Optical Alignment." Numbers in data tables should be tabular-lined (monospaced numbers) to ensure they don't jump when values update.
*   **Do** use high-contrast text (`on_background`) for critical values and low-contrast (`on_surface_variant`) for labels.

### Don't
*   **Don't** use 100% white (#FFFFFF). It causes eye strain in dark environments. Use `on_surface` (#e5e2e1).
*   **Don't** use rounded corners above `md` (0.375rem). Soft, "bubbly" corners undermine the reliability and technical authority of a SCADA system.
*   **Don't** use drop shadows to define structure. Use background tonal shifts.
*   **Don't** use standard "Success Green" if the system is in an "Alarm" state. Mute the greens to let the red `error` tokens dominate the visual hierarchy.
